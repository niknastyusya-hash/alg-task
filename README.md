# Task Manager - Многопоточная система обработки заказов

## Описание проекта

Консольное приложение, имитирующее работу склада или службы доставки. Заказы поступают, обрабатываются в фоновом режиме с использованием многопоточности, хранятся в коллекциях и валидируются с помощью кастомных аннотаций.

## Архитектура

### Компоненты

1. **Аннотации (annotations package)**
    - `@OrderType` - определяет тип заказа (URGENT/REGULAR)
    - `@Validate` - маркер для полей, требующих проверки
    - `@NotNull` - проверка на null
    - `@NotEmpty` - проверка на пустую строку

2. **Модель (model package)**
    - `Order` - сущность заказа с полями: id, customerName, product, priority, status, createdAt

3. **Хранилище (storage package)**
    - `OrderStorage` - централизованное хранилище для управления:
        - `BlockingQueue<Order>` - очередь входящих заказов
        - `ConcurrentHashMap<String, Order>` - хранилище обработанных заказов

4. **Сервисы (service package)**
    - `OrderProducer` - поток-производитель, создающий заказы
    - `OrderConsumer` - поток-потребитель, обрабатывающий заказы
    - `OrderProcessor` - бизнес-логика обработки заказов

5. **Валидация (validation package)**
    - `OrderValidator` - рефлексивная валидация на основе аннотаций

### Потоки

- **Producer**: 1 поток, создает заказы и добавляет в очередь
- **Consumers**: 3 потока, забирают заказы из очереди и обрабатывают их
- **ExecutorService**: управление жизненным циклом потоков
